## 3. 存储结构对比

### 旧方案（单表示法）
```json
{
  "id": "q_001",
  "stem": "已知椭圆 x²/4 + y²/3 = 1",
  "options": {"A": "2x-y-5=0", ...},
  "question_type": "单选题",
  "knowledge_points": ["椭圆"]
}
```

**问题：**
- ❌ 无法用于PDF渲染（格式不规范）
- ❌ 向量化不稳定（不同写法生成不同向量）
- ❌ RAG精度低（缺少语义信息）

### 新方案（双表示法）
```json
{
  "id": "q_001",
  "content": {
    "stem_latex": "已知椭圆 $\\frac{x^2}{4}+\\frac{y^2}{3}=1$",
    "stem_plain": "已知椭圆 x²/4 + y²/3 = 1",
    "options_latex": {"A": "$2x-y-5=0$", ...},
    "options_plain": {"A": "2x-y-5=0", ...}
  },
  "normalized_text": "已知椭圆x2/4+y2/3=1...",
  "description": "单选题：已知椭圆...，考查椭圆/焦点性质",
  "source_meta": {"region": "山东省", "year": 2025, ...},
  "question_type": "单选题",
  "knowledge_points": ["椭圆"]
}
```

**优势：**
- ✅ 可用于PDF渲染（stem_latex）
- ✅ 向量化稳定（normalized_text）
- ✅ RAG精度高（description）
- ✅ 内容对比准确（stem_plain）

## 4. 处理流程时间线

```
时间轴（以一道题目为例）

0ms    ┌─ 开始
       │
100ms  ├─ LaTeX规范化（LLM调用）
       │  └─ 耗时：~2000ms（主要瓶颈）
       │
2100ms ├─ 正则后处理
       │  └─ 耗时：~10ms
       │
2110ms ├─ 转换为普通文本
       │  └─ 耗时：~10ms
       │
2120ms ├─ 生成规范化文本
       │  └─ 耗时：~10ms
       │
2130ms ├─ 生成描述
       │  └─ 耗时：~10ms
       │
2140ms ├─ 向量化
       │  └─ 耗时：~500ms
       │
2640ms ├─ 存储到FAISS
       │  └─ 耗时：~10ms
       │
2650ms └─ 完成

总耗时：~2.65秒/题

优化建议：
- 批量处理（减少LLM调用次数）
- 异步处理（并行化）
- 缓存规范化结果（避免重复处理）
```

## 10. 故障排查指南

```
问题1：LaTeX规范化失败
├─ 原因：LLM调用超时或失败
├─ 解决：使用正则后处理作为备用
└─ 代码：见latex_normalizer.py中的try-except

问题2：向量维度不匹配
├─ 原因：使用了不同的Embedding模型
├─ 解决：确保所有题目使用同一个模型
└─ 代码：检查embedding_model的初始化

问题3：检索精度低
├─ 原因：normalized_text生成不当
├─ 解决：检查normalize_text()方法的实现
└─ 代码：确保移除了所有标点和格式

问题4：存储空间过大
├─ 原因：保存了太多冗余数据
├─ 解决：只保存必要的字段
└─ 代码：在to_dict()中过滤不需要的字段

问题5：处理速度太慢
├─ 原因：LLM规范化是主要瓶颈
├─ 解决：使用批量处理或异步处理
└─ 代码：见IMPLEMENTATION_CODE_PART2.md
```
